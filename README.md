## What You'll Learn

- Create Wardley maps from user needs to infrastructure
- Use maps for strategic decisions (build/buy/defer, timing, focus)
- Apply Theory of Constraints to find and work bottlenecks
- Map pipelines showing multiple approaches at different evolution stages
- Use submaps to manage complexity

## Workshop Format (3-3.5 hours)

Each section is a short talk, then group work, then a discussion. We learn to draw the map first, and use it for strategy at the end.

1. **Cup of tea** - Users, needs and the value chain. Exercises 1 and 2
2. **Evolution: the map wakes up** - Evolution, climate and co-evolution. Exercise 3
3. **Tea shop at rush hour** - Theory of Constraints and pipelines. Exercises 4A and 4B
4. **Strategy and the OODA loop, knowledge architecture** - Choosing a move, cutting a map down. Exercise 5
5. **A real map** - Event modeling tooling

## The Scenario: Harbour Insurance

6 product teams, ~40 developers, AI coding agents deployed.

**The puzzle:** Code written 3x faster, but delivery unchanged. PRs wait 3 days for review (was <1 day).

**Your task:** Map it, find the constraint, work it.

## Key Concepts

**Wardley Maps:**
- Y-axis: Visibility (high = user-facing, low = infrastructure)
- X-axis: Evolution (Genesis → Custom → Product → Commodity)
- Dependencies: What needs what
- Strategic moves: Where to invest, what to buy vs build

**Theory of Constraints:**
1. Identify the constraint
2. Exploit it (cheap wins)
3. Subordinate everything to it
4. Elevate it (long-term investment)
5. Repeat
