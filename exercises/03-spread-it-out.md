# Exercise 3: Spread it out

**Canvas step:** 6 (map)
**Time:** about 15 minutes
**After:** evolution, climate and co-evolution

## Your task

1. Take your value chain from Exercise 2. Keep every component at the same height.
2. Add the evolution axis: genesis, custom built, product, commodity.
3. Move each component sideways to the stage it is in today.
4. Users and needs stay at the top.
5. If you are stuck on a placement, the domain expert decides.

## The four stages

| Stage | What it looks like | Example |
| --- | --- | --- |
| Genesis | New, rare, uncertain. Nobody knows yet how to do it well | A brand-new way of working with AI agents |
| Custom built | Built for one context. A few people understand it | Your code review process, your domain model |
| Product (+rental) | Several competing products to choose from | CI tools, AI coding assistants |
| Commodity (+utility) | Standard, expected, paid per use | Cloud compute, Git, email |

Evolution describes the market, not how mature your own team is. Something new can still sit far right if it is a utility version of an old activity.

Practices evolve too. When servers became a utility, autoscaling replaced capacity planning. Now that writing code is close to a commodity, reviewing code will have to evolve as well.

## Back together

- What is a commodity now that was not two years ago?
- Which placement surprised you?
- Where did your group disagree?

## Afterwards: use appropriate methods

One way of working does not fit the whole map. Pick the way of working by the stage each component is in.

| | Genesis, custom built | Product | Commodity, utility |
| --- | --- | --- | --- |
| The goal | Learn fast | Get it right | Cut cost and variation |
| How we work | Agile: small experiments | Lean: improve the flow | Six Sigma: standardise and automate |
| How we get it | Build it ourselves | Buy it and fit it in | Rent it as a utility |
