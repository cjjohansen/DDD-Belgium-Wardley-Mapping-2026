# Exercise 2: Build the chain

**Canvas step:** 5 (value chain)
**Time:** about 15 minutes
**After:** picking your anchor

## Your task

1. Start from your anchor and its need, for example Management and "Time to market".
2. Ask "what does this need depend on?" Write each answer as a component below it, and draw a line.
3. Keep asking "what does this depend on?" for each component until you reach infrastructure.
4. Stack the components by visibility. What the user sees goes near the top. What the user never sees goes near the bottom.

Do not place anything on the evolution axis yet. That comes in Exercise 3.

## Reading a value chain

- Read down to ask how: how is this need met?
- Read up to ask why: why do we need this?
- Each line is a dependency. The component above pays money or effort, and gets a capability back.

## What can go on a map

- Activities: what we do, such as writing code or reviewing it
- Practices: how we do it, such as pair programming
- Data: facts we keep, such as the policy records
- Knowledge: what we understand, such as the insurance domain
- Things we use, such as the CI server

## Back together

- Where is the line between the problem domain and the solution domain?
- Which dependency was hardest to find?
- Did you reach infrastructure, or stop somewhere in the middle?
